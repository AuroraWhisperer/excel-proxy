# 直接登录与多账号

[项目首页](../readme.zh-CN.md) · [English](../readme.md) · [文档目录](README.md)

Windows 首页的 **手动登录** 使用 Excel/BPS 的设备码授权。点击按钮，在同一台电脑打开的 OpenAI 页面输入面板显示的设备码并确认授权。面板随后用所选模型发起一次 WebSocket 请求，收到模型文本后启用账号。

## 日常使用

- 首次登录自动保存账号，发送一次简短模型请求验证，成功后启用该账号、备份原 Codex 配置并写入连接配置/模型目录。首次接入后请重启 Codex。
- 添加账号会保留原账号；新账号验证成功才成为当前账号。验证失败时仍保留候选账号，用户可在高级设置更换测试模型后手动重试。
- 最多保存 50 个账号。选择器中的 **使用此账号** 只影响随后开始的请求，已开始的请求保留自己的身份。不会在 401、403 或额度不足时自动换账号。
- 同一账号重新登录会暂存新凭据，验证前不替换正在使用的凭据。删除当前账号会停止使用，重启后也不会回退到旧 Excel 缓存。
- 账号已启用且凭据未变化时，重复的启用请求不会重复消费验证额度。高级设置中的手动测试仍可重新验证当前模型。
- 登录或验证成功后关闭页面不会删除账号。若离开页面时授权刚完成、尚未自动验证，可返回后手动选中已保存账号启用。

## 账号密码登录与 JSON 文件

首页的 **自动登录** 和用量页的 **账号密码登录** 均使用 Excel/BPS 的浏览器 OAuth 授权流程：粘贴一行 `账号----密码---2FA密钥` 后，程序打开独立无痕会话，在官方页面填写账号、密码和本机计算的六位验证码，并在回调发往网络前通过本机浏览器调试通道直接截获授权码完成换票，不占用本机 1455/1457 端口。第三项填写 Base32 验证器密钥。支持三连字符、四连字符及混合分隔，以第一段和最后一段连续三个以上连字符作为分隔符，密码中间的连字符会保留。每次登录一个账号。

密码和密钥仅在本次流程的内存中使用，生成验证码依赖本机时间。验证码失效时请检查系统时钟，也可在登录窗口手动输入。人机验证、邮件验证码、工作空间选择和授权确认由本人完成。成功、取消或超时后程序关闭本次窗口。旧版用户请参阅[隐私与本地数据](privacy.md#数据会发往哪里)。

自动登录与手动登录复用同一个本机浏览器启动器，明确打开 Edge InPrivate 或 Chrome Incognito 独立窗口；项目虚拟环境中的 Playwright 通过本机临时端口连接该窗口填写表单，不再另外启动测试浏览器。每次使用独立临时用户目录，结束后关闭本次进程并清理目录。更新后需安装 `requirements.txt` 中的依赖，不需要下载额外浏览器。用量页的 **导入 JSON** 继续直接读取原有账号 JSON 文件，不走账密自动填写；首页登录成功后仍按原流程验证并启用连接，用量页登录仅添加额度查询账号。

首页的 **导入 JSON** 与两种登录方式并列，支持 Sub2API 的 `accounts[].credentials` 导出、Codex `auth.json` 的 `tokens` 对象、单个账号和账号数组，每次最多 50 个账号、文件不超过 1 MB。单账号导入后自动测试连接，通过后启用账号、同步额度查询账号并配置 Codex，与账密登录成功后的流程相同；多账号文件先保存，再从选择器中选择账号并点击 **使用此账号**。测试失败保留候选账号和原连接；重新导入当前账号时，新凭据验证通过前不会替换正在使用的凭据。

JSON 必须包含 OAuth `access_token`，并提供可读取的账号 ID 和有效期（可从访问令牌中提取）。嵌套的 `refresh_token` 会一并加密保存并用于续期；已过期但含刷新令牌的账号会在启用前尝试续期，只有访问令牌的账号失效后需重新登录或导入。API Key、仅含刷新令牌、其他平台或无效账号会使整批导入失败。导出文件中的代理地址、分组、调度设置和其他管理元数据不参与请求。用量页的 JSON 导入仍只用于额度查询及连接测试，不启用连接账号、不保存刷新令牌。

## 凭据与续期

连接账号存于配置目录的 `proxy-accounts.dpapi`，使用当前 Windows 用户的 DPAPI 加密并原子替换。保存 access token、授权服务器返回的 refresh token、有效期和明确选择的账号；不保存密码、验证码、ID token。公开状态只返回邮箱、脱敏账号提示、有效期和状态，不返回任何 token。

Excel 设备码和自动登录账号均使用 Excel/BPS OAuth 应用 ID 续期；旧版导入的 Codex 授权按原应用 ID 续期。凭据临近到期时，并发请求共用一次刷新。刷新令牌轮换后加密保存新值，未返回新刷新令牌时保留旧值。续期校验账号身份，永久授权失败时提示重新登录。

访问令牌也可能在标记的到期时间之前被服务端撤销。Responses 初始请求或前置图片上传明确返回 HTTP 401 时，服务只对被拒绝的同一已选账号续期，并最多重发一次；并发的旧令牌 401 复用已刷新的凭据，不重复轮换。不会取用待验证的新登录、切换账号或回退 Excel 缓存。刷新本身返回永久授权失败时，账号立即显示需要重新登录。若账号在刷新过程中切换，则保留原账号的新凭据但停止重发。上游已经接受生成后，纠错请求的 401 不会触发整轮重发；403、429、5xx 和读写中断也不触发此认证重试。新登录的验证请求始终验证原来的候选凭据。

新账号成功启用时，仅将 access token 同步给原有余额查询账号库。余额查询库仍不持有 refresh token；从连接页或用量页移除账号时，会同时移除两个列表中的同一账号。余额查询自身的缓存、过期处理仍遵循原有规则。数据目录及日志范围见[隐私与本地数据](privacy.md)。

## 实现与验证

- `app/account_login.py`：复用官方授权生命周期，余额登录与服务登录使用不同的保存目标。
- `app/proxy_accounts.py`：加密账号库、暂存重登录凭据、明确选择与单次并发刷新。
- `app/proxy.py`：本机账号 API、真实模型验证、自动配置，以及 Responses/图片请求的按次凭据选择。
- `tests/test_proxy_accounts.py`：多账号、续期、重登录隔离、失败回滚、本机访问限制和持久化回归。

开发测试使用隔离目录、模拟官方授权/模型响应和禁止真实 HTTP 的离线运行器。浏览器测试不等同于真实账号权限验证；真实官方登录、续期及模型调用需要用户在应用中验收。不要把真实凭据或登录响应写入 Git、日志或截图。
