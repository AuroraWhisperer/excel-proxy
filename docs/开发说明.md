源码按程序、测试和脚本分开，文件按当前职责命名。`.venv/` 是运行环境；`tmp/` 保存本地历史资料、停用代码和临时文件，清理目录中的 `manifest.json` 记录原路径与校验值。以上目录以及 `.tmp/`、`__pycache__/` 均不提交。

`tools/probe-first-output.py` 会真正发送请求，仅在需要测上游延迟时手动运行。`tools/run-offline-tests.py` 是离线测试，两者用途不同。

`tools/refresh-excel-session-macos.py` 从 macOS Excel 缓存读取已登录会话并提交给本机本地服务。Windows 仍使用 `启动.vbs`；仓库位置和 AppData 中的设置、日志与历史目录保持兼容。

公共模型接口及会话对象仍可从 `excel_upstream` 访问，但只需要模型信息的新代码应直接依赖 `excel_models`。共享凭证能力不应反向依赖额度业务模块；底层模块也不应导入 `proxy`。`test_module_boundaries` 检查静态导入环及这些模块边界，重放缓存测试在存储所属模块设置测试替身。

工具和历史转换的既有入口仍可从 `excel_upstream` 调用，输入与压缩的既有入口仍可从 `responses_protocol` 调用；实际实现只保留一份。新增调用方直接依赖负责该功能的模块。`SSEUsageCapture` 保留 `usage_tracking` 导入路径，记录规范化与流解析分别由 `usage_records`、`usage_capture` 维护。

账号路由通过 `AccountRouteDependencies` 接收请求编排能力，流式处理通过 `StreamDependencies` 接收用量记录与收尾回调。测试替身应设置在实际所属模块或这些依赖对象上。用量归档提交、日志替换失败后的回滚顺序，以及流式取消和一次性收尾都有离线回归覆盖。提示词归档仍由 `proxy.py` 与 `util.py` 配合处理，运行数据目录和存储格式保持兼容。

## 启动和验证

在仓库根目录运行，Windows：

```powershell
./.venv/Scripts/python.exe -B app/proxy.py
```

离线回归使用隔离的设置、状态和缓存目录，并阻止真实 httpx 传输：

```powershell
./.venv/Scripts/python.exe -B tools/run-offline-tests.py
```

只检查某一部分，可以追加 unittest 的模块、类或方法名：

```powershell
./.venv/Scripts/python.exe -B tools/run-offline-tests.py test_local_access test_excel_images
```

macOS 将 Python 路径换成 `./.venv/bin/python`。不要运行全仓库 pytest 自动发现，也不要搜索或修改生成的 `mutants/` 目录。GitHub Actions 使用同一个离线入口。

修改用量页倒计时后，另运行 JavaScript 回归：

```powershell
node --test tests/test_quota_countdown.js
```

## 本地接口

默认地址为 `http://127.0.0.1:8000`。下面的模型接口也支持去掉 `/v1` 的路径。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/models` | 获取本地模型列表；不要求先登录。 |
| `POST /v1/responses` | 文本、看图、流式回复及客户端工具调用。 |
| `POST /v1/responses/compact` | 生成供下一轮继续使用的上下文摘要。 |
| `POST /v1/images/generations` | 生成图片。 |
| `POST /v1/images/edits` | 编辑图片。 |

连接与设置在 `/ui`，最近请求在 `/ui/requests`，用量与费用在 `/ui/usage`，根路径会跳转到首页。所有入口统一检查真实连接来源、Host 和浏览器来源；浏览器必须同源，本机原生客户端可以不带 Origin。服务入口关闭了网络转发头信任，不把 `X-Forwarded-For` 当作实际连接来源。

接口接收 JSON 对象。数组、数字、字符串、null 或损坏的 JSON 返回 400。损坏 JSON 的日志只保存路径、编码、长度等诊断信息，不打印正文片段或正文的十六进制值。

### 模型

| 模型 ID | 推理级别 |
| --- | --- |
| `gpt-6-astra-excel` | `medium`、`high`、`xhigh` |
| `gpt-5.6-luna-excel` | `low`、`medium`、`high`、`xhigh` |
| `gpt-5.6-terra-excel` | `low`、`medium`、`high`、`xhigh` |
| `gpt-5.6-sol-excel` | `low`、`medium`、`high`、`xhigh` |

Responses 请求接受省略 `-excel` 的别名。省略模型时使用 `gpt-5.6-sol-excel`；未知模型返回 400。模型是否真正可用仍由账号权限决定。

### 工具、历史与流式回复

客户端的工具定义会写入请求说明。Excel 返回的 `run_officejs` 在这里用来传递调用信息，本地服务把它还原成客户端声明的 function、custom 或 namespace 工具；本地服务不执行里面的代码。

对目录中标明 `raw_fields` 的工具，默认指引使用原文传输：目录的 `transport` 给出准确的 `summary` 标记和首选字段，`summary` 形如 `excel-proxy.raw/FIELD/TOOL_NAME`，`code` 保存未改写的原文，`extended_summary` 保存其他参数的 JSON 对象字符串。仅支持显式声明为字符串的 `exec_command.cmd`、函数工具的 `code`，以及 custom 工具的 `input`；工具全名必须与目录完全一致。custom 工具没有其他参数。命令中的引号、反斜杠、中文、换行和末尾空白都保留。其他工具、未提供可选原文字段的调用，以及旧客户端历史仍支持 JSON 封装；外层原生工具参数始终需要合法 JSON。

函数参数使用固定版本 `jsonschema==4.26.0` 校验，支持声明的草案、组合约束和本地引用，不读取远程或文件引用。schema 上限 1 MiB，schema 和参数的嵌套深度上限 128、节点上限 65,536；关键字校验有 65,536 步预算，嵌套草案也受约束。这些是结构和步骤限制，不是任意正则表达式的硬超时保证；`format` 未额外启用断言。

封装纠错最多请求一次，且下发前必须证明工具目标、原始文本和其余参数未改变。无法证明等价的损坏 JSON 不会被另一个命令替换；返回明确错误，由客户端重新生成。未封装原文可在文本完全不变时转成声明工具的封装。纠错沿用任务和用户轮次，并递增 `agent_iteration`；继续计入用量，保留流式取消和保活行为。

`unknown_tool` 使用单独的首次重新生成路径：当前请求有工具目录、原始和转换后历史均没有工具调用/结果或压缩项、上游已完成，且最后一项是唯一的未知函数调用时，才从原请求补充目录提醒再生成一次。包括封包内的未知目标和直接调用未声明内部助手的情况；不回传失败调用的代码，不伪造已执行的工具结果，不推测替换目标。新结果必须恰好包含一个通过完整目录和 schema 校验的调用。它与封装纠错共享一次恢复预算；已有工具历史、整批多工具或第二次失败直接报错。此路径允许模型重新选择首次调用，不能把它当成损坏命令的等价修复。

原文封包结构完整、但标记中的精确工具名未声明时，同样归类为 `unknown_tool`，不再误报 JSON 格式错误。元数据损坏、原文字段冲突或不支持的字段仍属于封包错误。`tool_choice=none` 禁止重新生成工具调用。

工具失败的 `tool_call_diagnostics` 在不符合恢复条件时也会写入请求 trace、用量记录及归档，无需开启全文调试。未知工具记录目标来源（原文/JSON 封包/直接调用）、名称、当前目录名称及摘要、未恢复原因；只接受最长 128 字符的工具标识，最多列出 64 个声明名称，其他名称仅保留摘要，不包含参数、代码、schema 或提示词正文。请求记录页显示未知工具名称和是否因已有历史、多工具批次、工具未开放等原因停止恢复。旧日志没有保存的目标名称无法事后还原。

整批工具必须全部校验成功后才会发给客户端，也只在这时写入重放缓存。未知工具、重复 ID 或未完成的调用不会先执行其中的有效部分。客户端设置 `parallel_tool_calls=false` 时，多个调用会被拒绝。

恢复历史时，缓存记录还必须与客户端给出的工具全名、JSON 参数或 custom 原文相符，不能仅凭相同的调用 ID 替换参数。JSON 的空白和键顺序不影响匹配；大整数和 custom 原文不会被改写。缓存不匹配时使用现有的历史重建路径，不借用另一条调用的内容。重建时依据本轮目录为符合条件的命令、代码和 custom 输入生成原文封包，避免历史继续示范嵌套 JSON；有匹配缓存的原生调用保留原样，维持上游身份连续性。历史中的旧工具不会自动变成本轮可执行工具。

`arguments.code` 上的 `missing_comma` 表示内层字符串未能作为 JSON 解析，不一定是命令本身缺逗号；未转义的内嵌引号也会触发它。原文传输去掉源码的内层 JSON 编码，由本地服务序列化最终客户端参数，但它仍依赖上游正确选择工具和生成外层参数，不能保证任意错误模型输出都能恢复。不要用猜测补引号、删字段或关闭校验来隐藏错误。参考项目的具体边界见[参考项目与改进](参考项目与改进.md)。

流式等待每 15 秒保活。上游忽略流式请求而返回普通 JSON 时，本地服务先转换为 Responses 事件，再进入同一套文本、工具批次、终止状态和用量校验，向客户端保持 `text/event-stream`。只有响应有真实 ID、输出项连续且全部完成，并以完整工具调用或明确最终回答结束时，才补全缺失的终止事件。仅有进度说明、半截参数或明确失败不会当作成功。开始生成后的传输错误不会自动重放整个请求。初始连接失败和错误正文读取失败保留具体异常类型，区分 502 连接错误、504 超时和本地工具协议错误。

请求需携带完整历史；`previous_response_id`、强制工具选择目前返回 400。`text.format` 的 `json_object` 和 `json_schema` 通过开发者指令与本地校验兼容，用于 Codex 自动标题、描述和回合摘要。流式结构化消息在完成并校验后统一发出，以完成项重建事件，不回放未经校验的文本增量；普通文本和推理摘要仍增量转发。JSON 或 Schema 不匹配返回 `excel_invalid_structured_output`，不额外请求模型重试或编造结果。这是本地服务适配，不是上游原生约束解码；Schema 只允许文档内引用。推理摘要请求统一映射为 Excel 支持的 `auto`，没有上游摘要时不编造。上下文压缩失败时保留原历史。

### 图片

看图的内嵌格式限定为 PNG / JPEG / GIF / WebP；单张 20 MiB、单请求 20 张、解码后合计 32 MiB。消息和工具结果一起计入限制，完整检查通过后才上传消息附件。不同图片独立等待，同账号同图共享上传；工具结果保留原有内嵌内容。该检查不包含图片尺寸或像素内容解码。

生图和编辑均接收 JSON，使用 `gpt-image-2`，返回 PNG 的 `data[].b64_json`：

- `prompt` 必填；`n` 为 1–3，默认 1。
- `size`：`auto`、`1024x1024`、`1536x1024`、`1024x1536`、`1280x720`。
- `quality`：`auto`、`low`、`medium`、`high`；`background`：`auto` 或 `opaque`。
- 编辑使用 `images: [{"image_url": "data:image/png;base64,..."}]`，接受 1–3 张 PNG / JPEG / WebP，每张最多 20 MiB。本地服务转换成上游需要的 multipart，不自行下载远程图片。
- 不支持客户端直接提交 multipart、遮罩、透明背景、图片流式输出或非 PNG 输出。

托管 Codex 配置里的 `x-openai-actor-authorization = "excel-proxy"` 是图片工具接入标记，不是登录凭据。实际认证使用用户明确选中的直接登录账号，或高级设置中显式选择的 Excel 缓存会话。实现与安全边界见[直接登录与多账号](direct-login.md)。

## 设置和运行数据

Windows 的设置在 `%APPDATA%\ghcp_proxy`，会话、日志及历史在 `%LOCALAPPDATA%\ghcp_proxy`。macOS 状态在 `~/Library/Application Support/ghcp_proxy`，缓存在 `~/Library/Caches/ghcp_proxy`。源码整理不移动这些目录。

`excel-native-calls.sqlite3` 保存重放需要的工具参数。单条序列化载荷上限 4 MiB；内存最多 512 条或 8 MiB 序列化载荷；磁盘最多 8,192 条或 64 MiB 载荷，写入时清理超过 60 天未使用的项，读取不会复活过期项。容量不足时淘汰最近较少使用的旧记录，保留当前批次；当前批次本身超限则整批拒绝。写入采用单个事务，成功提交后才更新内存；旧三列表自动补充字节计数。数据库配额不包含 SQLite 页和索引开销，已有文件的空闲页会复用但不会立即缩小文件。缓存淘汰后的旧调用沿用历史重建路径，不承诺永久保存原始身份。全文调试记录默认关闭，但工具历史数据库仍会工作。旧目录名 `ghcp_proxy` 和 `GHCP_*` 环境变量继续保留，以兼容现有数据。

账号额度和 API 费用估算已放在 `/ui/usage`，具体导入、登录和统计周期见[账号额度](account-balances.md)。费用估算不是实际账单，也不是 Excel 剩余额度。`/api/account-quota` 仍保留为可选接口，查询本机 Codex 登录账号的订阅额度，不是 Excel 额度。

| 环境变量 | 用途 |
| --- | --- |
| `GHCP_UPSTREAM_TIMEOUT_SECONDS` | 非流式请求超时，默认 300 秒。 |
| `GHCP_UPSTREAM_PROXY` | HTTP / HTTPS 上游网络转发。 |
| `GHCP_HTTP_PROXY`、`GHCP_HTTPS_PROXY` | 分协议设置网络转发。 |
| `GHCP_NO_PROXY` | 直接连接的主机。 |
| `GHCP_UPSTREAM_TLS_VERIFY` | TLS 证书校验开关。 |

也会读取标准 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。Excel 请求使用 HTTP/1.1。项目路径改变后，登录启动和终端快捷命令需在面板重新安装。
