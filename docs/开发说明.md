源码按程序、测试和脚本分开，文件按当前职责命名。`.venv/` 是运行环境；`tmp/` 保存本地历史资料、停用代码和临时文件，清理目录中的 `manifest.json` 记录原路径与校验值。以上目录以及 `.tmp/`、`__pycache__/` 均不提交。

`tools/probe-first-output.py` 会真正发送请求，仅在需要测上游延迟时手动运行。`tools/run-offline-tests.py` 是离线测试，两者用途不同。

日常排查可先执行 `curl.exe -i http://127.0.0.1:8000/healthz` 查看本地状态。确需测量一次真实生成时，在 Windows 项目目录运行 `.\.venv\Scripts\python.exe -B tools/probe-first-output.py --live --efforts medium --output latency.jsonl`。输出目标须为新文件，省略 `--output` 时打印到终端。一轮最长 120 秒，报告记录 HTTP 状态、首字节、首个有效输出、终态和用量，正文与授权头不进入报告。

Windows 仍使用 `启动.vbs`；仓库位置和 AppData 中的设置、日志与历史目录保持兼容。

公共模型接口及会话对象仍可从 `excel_upstream` 访问，但只需要模型信息的新代码应直接依赖 `excel_models`。共享凭证能力不应反向依赖额度业务模块；底层模块也不应导入 `proxy`。`test_module_boundaries` 检查静态导入环及这些模块边界，重放缓存测试在存储所属模块设置测试替身。

工具和历史转换的既有入口仍可从 `excel_upstream` 调用，输入与压缩的既有入口仍可从 `responses_protocol` 调用；实际实现只保留一份。新增调用方直接依赖负责该功能的模块。`SSEUsageCapture` 保留 `usage_tracking` 导入路径，记录规范化与流解析分别由 `usage_records`、`usage_capture` 维护。

账号路由通过 `AccountRouteDependencies` 接收请求编排能力，流式处理通过 `StreamDependencies` 接收用量记录与收尾回调。测试替身应设置在实际所属模块或这些依赖对象上。用量归档提交、日志替换失败后的回滚顺序，以及流式取消和一次性收尾都有离线回归覆盖。提示词归档仍由 `proxy.py` 与 `util.py` 配合处理，运行数据目录和存储格式保持兼容。

## 启动和验证

在仓库根目录运行，Windows：

```powershell
./.venv/Scripts/python.exe -B app/proxy.py
```

离线回归使用隔离的设置、状态和缓存目录，并阻止真实 httpx 传输：

```powershell
./.venv/Scripts/python.exe -B tools/run-offline-tests.py
```

只检查某一部分，可以追加 unittest 的模块、类或方法名：

```powershell
./.venv/Scripts/python.exe -B tools/run-offline-tests.py test_local_access test_excel_images
```

macOS 将 Python 路径换成 `./.venv/bin/python`。不要运行全仓库 pytest 自动发现，也不要搜索或修改生成的 `mutants/` 目录。GitHub Actions 使用同一个离线入口。

修改用量页倒计时后，另运行 JavaScript 回归：

```powershell
node --test tests/test_quota_countdown.js
```

## 工具协议与请求生命周期

接口列表、模型 ID、结构化输出和图片参数见 [API 与兼容范围](api.md)。这里记录维护这些能力时需要了解的内部协议。

客户端的工具定义以说明文本写入协议，保留参数 schema 的必填项、枚举、引用和其他约束。调用方显式提供的 `instructions` 单独放在前面，随后只有一条协议开发者消息，再接客户端完整历史；结构化输出要求追加到这条协议消息末尾。默认布局没有额外提醒或尾部目录开关。Excel 返回的 `run_officejs` 用来传递调用信息，本地服务把它还原成客户端声明的 function、custom 或 namespace 工具；本地服务不执行里面的代码。

FUNCTION 工具把一个 `{"name":"CATALOG_NAME","arguments":{...}}` JSON 对象序列化到 `code`，`arguments` 必须是对象。CUSTOM 工具使用精确的 `summary="codex2api.custom/CATALOG_NAME"` 标记，`code` 直接保存原始输入，不再包一层 JSON 或 Markdown。工具名包含完整命名空间；外层参数还包含 `extended_summary`、`destructive=false` 和 `references=[]`。默认协议要求一次调用一个客户端工具，`update_plan` 同样通过 `run_officejs` 传输，得到结果后继续任务。

旧的 `excel-proxy.raw/FIELD/TOOL_NAME` 封包仍可兼容解析，但新目录和恢复指令不再引导生成这种封包。外层原生参数始终必须是合法 JSON；FUNCTION 的内层字符串也必须正确转义引号、反斜杠和控制字符。

函数参数使用固定版本 `jsonschema==4.26.0` 校验，支持声明的草案、组合约束和本地引用，不读取远程或文件引用。schema 上限 1 MiB，schema 和参数的嵌套深度上限 128、节点上限 65,536；关键字校验有 65,536 步预算，嵌套草案也受约束。这些是结构和步骤限制，不是任意正则表达式的硬超时保证；`format` 未额外启用断言。

封装纠错最多请求一次，且下发前必须证明工具目标、原始文本和其余参数未改变。无法证明等价的损坏 JSON 不会被另一个命令替换；返回明确错误，由客户端重新生成。未封装原文可在文本完全不变时转成声明工具的封装。纠错保留原任务输入并递增 `agent_iteration`，派发时按获得的账号槽位确定 `task_id`，创建新的 `turn_id`；继续计入用量，保留流式取消和保活行为。

`unknown_tool` 使用单独的首次重新生成路径：当前请求有工具目录、原始和转换后历史均没有工具调用/结果或压缩项、上游已完成，且最后一项是唯一的未知函数调用时，才从原请求补充目录提醒再生成一次。包括封包内的未知目标和直接调用未声明内部助手的情况；不回传失败调用的代码，不伪造已执行的工具结果，不推测替换目标。新结果必须恰好包含一个通过完整目录和 schema 校验的调用。它与封装纠错共享一次恢复预算；已有工具历史、整批多工具或第二次失败直接报错。此路径允许模型重新选择首次调用，不能把它当成损坏命令的等价修复。

原文封包结构完整、但标记中的精确工具名未声明时，同样归类为 `unknown_tool`，不再误报 JSON 格式错误。元数据损坏、原文字段冲突或不支持的字段仍属于封包错误。`tool_choice=none` 禁止重新生成工具调用。

工具失败的 `tool_call_diagnostics` 在不符合恢复条件时也会写入请求 trace、用量记录及归档，无需开启全文调试。未知工具记录目标来源（原文/JSON 封包/直接调用）、名称、当前目录名称及摘要、未恢复原因；只接受最长 128 字符的工具标识，最多列出 64 个声明名称，其他名称仅保留摘要，不包含参数、代码、schema 或提示词正文。请求记录页显示未知工具名称和是否因已有历史、多工具批次、工具未开放等原因停止恢复。旧日志没有保存的目标名称无法事后还原。

整批工具必须全部校验成功后才会发给客户端，默认响应转换不写入原生调用缓存。未知工具、重复 ID 或未完成的调用不会先执行其中的有效部分。客户端设置 `parallel_tool_calls=false` 时，多个调用会被拒绝。

恢复历史时，只使用本次提交的完整调用重建 `run_officejs`，不查持久缓存，也不依赖本轮目录重写旧参数。FUNCTION 历史使用 `{"name":...,"arguments":{...}}`，CUSTOM 历史使用 `{"name":...,"input":...}` JSON 封包；CUSTOM 的新输出仍使用上面的原文标记协议。工具结果必须能在同一份历史中找到先前的调用，否则在派发前返回 400。空结果、错误文本、消息归属和 `agent_message` 类型保持原意，原生压缩项及其之前的历史不会被本地裁剪；历史中的旧工具不会自动变成本轮可执行工具。

`arguments.code` 上的 `missing_comma` 表示内层字符串未能作为 JSON 解析，不一定是命令本身缺逗号；未转义的内嵌引号也会触发它。CUSTOM 原文传输减少了输入文本的一层 JSON 编码，FUNCTION 仍使用完整 JSON 封包。两者都依赖上游正确选择工具和生成外层参数，不能保证任意错误模型输出都能恢复。不要用猜测补引号、删字段或关闭校验来隐藏错误。参考项目的具体边界见[参考项目与改进](参考项目与改进.md)。

流式等待每 15 秒保活。上游忽略流式请求而返回普通 JSON 时，本地服务先转换为 Responses 事件，再进入同一套文本、工具批次、终止状态和用量校验，向客户端保持 `text/event-stream`。只有响应有真实 ID、输出项连续且全部完成，并以完整工具调用或明确最终回答结束时，才补全缺失的终止事件。仅有进度说明、半截参数或明确失败不会当作成功。开始生成后的传输错误不会自动重放整个请求。初始连接失败和错误正文读取失败保留具体异常类型，区分 502 连接错误、504 超时和本地工具协议错误。

### 图片

看图的格式与容量限制见 [API 与兼容范围](api.md#图片输入)。先规范化消息和工具结果中的文本、图片，并校验内容类别、HTTPS URL、`detail` 和内嵌数据限制，完整检查通过后才上传消息附件。不同图片独立等待，同账号同图共享上传；工具结果的图片留在原结果中，不提取成新消息。该检查不包含远程图片下载、图片尺寸或像素内容解码。

生图、编辑参数及客户端接入标记见 [API 与兼容范围](api.md#图片生成与编辑)。

## 设置和运行数据

平台数据目录、凭据保存和日志范围见[隐私与本地数据](privacy.md)。以下记录缓存实现与运行选项；旧目录名 `ghcp_proxy` 和 `GHCP_*` 环境变量继续保留，以兼容现有数据。

默认生成路径不再读写 `excel-native-calls.sqlite3`，继续任务依靠客户端随请求提交的完整调用和结果；旧数据库容量不会导致新工具批次被拒绝。兼容模块及已有数据库文件保留，升级不会删除旧记录，其中可能仍有过去保存的命令、代码和参数。全文调试开关也不会自动清除这些文件。

上游缓存键仅来自顶层显式 `prompt_cache_key`，其原始字符串与调用作用域一起哈希；不再从会话字段回退，也不使用旧缓存转发开关。模型选择、推理强度和输入限制见 [Responses 兼容范围](api.md#responses-兼容范围)。

Codex 接入使用支持的裸模型名，例如 `gpt-6-astra`，并由 Codex 提供自身的模型指令。安装流程不再生成或挂载项目模型目录，也不附加项目自定的基础指令、verbosity 或截断覆盖。迁移只删除指向项目自有目录的 `model_catalog_json`；托管配置中与旧默认一致的上下文窗口参数也会移除，旧 `-excel` 选择转换为对应裸模型名。用户自有目录、其他自定义设置和原配置备份保留；旧目录文件不会因解除引用而自动删除。

账号额度和 API 费用估算已放在 `/ui/usage`，具体导入、登录和统计周期见[账号额度](account-balances.md)。费用估算不是实际账单，也不是 Excel 剩余额度。`/api/account-quota` 仍保留为可选接口，查询本机 Codex 登录账号的订阅额度，不是 Excel 额度。

| 环境变量 | 用途 |
| --- | --- |
| `GHCP_UPSTREAM_TIMEOUT_SECONDS` | 非流式请求超时，默认 300 秒。 |
| `GHCP_UPSTREAM_PROXY` | HTTP / HTTPS 上游网络转发。 |
| `GHCP_HTTP_PROXY`、`GHCP_HTTPS_PROXY` | 分协议设置网络转发。 |
| `GHCP_NO_PROXY` | 直接连接的主机。 |
| `GHCP_UPSTREAM_TLS_VERIFY` | 直连及经过代理时均默认校验证书。企业 CA 通过 `SSL_CERT_FILE` 指向 PEM 信任包。 |
| `GHCP_GENERATION_CONCURRENCY` | 每个账号的生成并发数，默认 4，可设 1–20。 |
| `GHCP_GENERATION_MAX_PENDING` | 进程等待槽位的请求数上限，默认 64，可设 0–64。0 表示槽位满时直接返回 429。 |
| `GHCP_GENERATION_WAIT_SECONDS` | 每次生成的本地排队与启动等待预算，默认 30 秒，可设 1–300 秒。 |
| `GHCP_UPSTREAM_STARTS_PER_SECOND` | 所有账号合计每秒最多开始几次生成连接（含连接重试），默认 0，即关闭此限速；可设 0–5。它限制建连前的启动次数，不保证握手完成后 `response.create` 的精确发送速率。 |

也会读取标准 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`。生成请求使用 WebSocket，附件和图片接口使用 HTTPS。`GHCP_EXCEL_RESPONSES_URL` 可以指向本地 `ws://` 协议测试服务，也支持现有的自定义 HTTP 后端。项目路径改变后，登录启动和终端快捷命令需在面板重新安装。

服务启动时先独占状态目录中的 `service.lock`，再加载应用、迁移数据和处理 Codex 配置。退出或进程终止时由操作系统释放锁。锁文件可以保留，升级前正常关闭现有服务。

状态目录中的 `task.key` 保存本机的持久任务密钥。生成请求获准占用账号槽位后，以密钥、账号及用户身份、槽位编号派生稳定的 `task_id`，每次派发生成创建新的 `turn_id`；仅连接建立阶段的重试保留该 turn。续期不会改变账号身份，升级和迁移应保留 `task.key`。现有密钥损坏会报错；文件缺失时会创建新命名空间。

请求完成记录保留派发的 `upstream_model`、`upstream_identity` 和上游返回的 `response_model`。开启原文调试时，请求转储在槽位身份注入后生成，记录交给传输层的 JSON payload；WebSocket 层仍会补入 `response.create`、请求/恢复标识并强制 `stream=true`，因此该转储不是完整 WS 帧或握手抓包。排队拒绝的请求不会生成出站转储。开始事件仍描述准备阶段的请求。工具纠错另在 `tool_call_recovery.upstream_identity` 中记录该次派发身份。

接口行为见 [API 与兼容范围](api.md)，其他文档见[文档目录](README.md)。
