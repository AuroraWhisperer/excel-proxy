## 工具封包专项复核（2026-09-27）

本次通过 GitHub API 固定核对 Sub2API `production` 的 `dcf523bf1da062f25cde3a129e3e129398f1f4ec` 和 bridge `main` 的 `8a277dfcdbb647d2ef4d714e31b6a98260a63a79`。结论不是“参考项目永不出错”：

- Sub2API 为命令、代码和 custom 输入指定原文传输，同时把[未命中缓存的历史调用](https://github.com/ranxi2001/sub2api/blob/dcf523bf1da062f25cde3a129e3e129398f1f4ec/backend/internal/service/basispoints/tools.go#L364)重建为相同格式。其[纠错实现](https://github.com/ranxi2001/sub2api/blob/dcf523bf1da062f25cde3a129e3e129398f1f4ec/backend/internal/service/basispoints/tool_repair.go)最多生成两次修正，保留操作内容；[适配器说明](https://github.com/ranxi2001/sub2api/blob/dcf523bf1da062f25cde3a129e3e129398f1f4ec/backend/internal/service/basispoints/README.md#tool-transport-corrections)明确不提供受约束解码或任意损坏输出必能恢复的保证。
- bridge 的[封包解析器](https://github.com/Kaixxrua/excel-codex-bridge/blob/8a277dfcdbb647d2ef4d714e31b6a98260a63a79/src/excel_codex_bridge/excel_upstream.py#L396)仍解析内层 JSON，兼容非法反斜杠和包裹文本；它没有消除内嵌引号损坏的来源，也不能当作“永远解决缺逗号”的实现。

本地日志中，2026-09-27 10:43–11:28（北京时间）的 12 条失败 trace 是 `invalid_transport_envelope`；12:28–12:29 的另外 22 条是 `unknown_tool`，不能混为同一种故障。用量日志有 13 次纠错因 `repair_changed_input` 被拒绝：无法解码原调用时，本地服务不能证明改写后的命令等价。日志没有保存失败调用的源码，无法确认每个出错字符，也不能据此认定最近的未知工具具体是哪一个。

上一轮只调整默认生成指引，未改历史重建路径。本次补上按当前目录重建原文历史、逐工具准确传输标记、纠错 `agent_iteration` 递增，并把未知工具的提示与 JSON 转义区分开。保留本项目整批校验、一次恢复预算、缓存身份及封装纠错的参数一致性约束；不照搬网关的放宽 schema 校验。两类参考实现都无法让本地适配器替代上游的原生工具 schema 约束。

随后参考 Sub2API 的[首次未知工具恢复](https://github.com/ranxi2001/sub2api/blob/dcf523bf1da062f25cde3a129e3e129398f1f4ec/backend/internal/service/basispoints/unknown_tool_repair.go)，补上从原请求重新生成一次的路径：必须尚无工具历史、只有一个完成的未知函数调用且位于末尾。不把失败调用或伪造结果放回历史；新结果继续经过本项目完整 schema 校验。本地同时覆盖直接误调未声明内部助手的情况，参考实现仅接受 `run_officejs` 外壳；两者都不是把旧命令猜改成另一条命令。多工具批次、已有执行历史和重复失败不启用此路径。

此复核说明取代下方历史记录中的“默认仍用 JSON 封装”表述。离线回归不能当作真实模型永不再犯错的证明。

### 502 / 504 和账号授权核查

核查的当日用量样本包含 42 次 502、8 次 504。其中 34 次 502 是上游 HTTP 200 后本地工具转换失败，并非服务端拒绝；其余记录包含连接中断，7 条旧记录缺少具体异常类型，不能据此认定上游宕机。已修复普通 JSON 上游响应到流式客户端的转换、初始网络异常分类，以及请求接续被阻止时引用未绑定异常变量的问题。保持只对明确的连接建立失败做有限重试，不在超时或已接受生成后盲目重放。

真实请求另确认当前已选账号返回 401 / `token_revoked`，本地到期时间尚未到；同账号续期也返回 401。新增提前撤销后的单次续期路径，并将永久失效显示为需要重新登录。用户选择稍后登录，因此本轮真实工具生成验证未完成，也没有执行模型返回的命令。具体认证边界见[直接登录与多账号](direct-login.md)。

### 本轮选择性补齐

- **原始传输和无损纠错：** 扩展现有 `run_officejs` 协议，命令/code/custom 原文可使用显式标记传输；拒绝纠错时更换命令、目标或元数据。默认 JSON 封装保留。
- **标准参数校验：** 用维护中的 JSON Schema 实现覆盖边界、组合约束、布尔 schema 和本地引用，限制结构与校验步骤，不允许远程引用。
- **回放容量：** 增加单条、内存与磁盘载荷上限；整批事务写入，保留原有 60 天期限及重启恢复，不照搬网关的两小时期限。
- **默认测试覆盖：** 将原本未被 unittest 发现的三个历史 ID 检查纳入默认回归，并新增协议、纠错和缓存反例。

不增加网络节点池、Mihomo 节点排名、403 自动分组、远端账号调度或 920k 压缩阈值；这些不符合当前本机项目职责或已声明上下文范围。附件和批次校验已有实现，不重复添加。`additional_tools` 目录继承暂缓，避免把其他轮次工具默认为本轮授权；没有引入新的多租户回放隔离保证。具体协议、限制和运行方式见[开发说明](开发说明.md)。

## 这次实际改了什么

### 1. 让本地接口真正只给本机使用

原来服务虽然只监听本机，但多数接口没有统一检查请求来自哪里。现在会检查连接地址、Host 和浏览器来源。外部网页、外部 Host、非本机连接会被拒绝，读取请求正文之前就结束。

参考桥接项目直接拒绝所有带 Origin 的浏览器请求。本项目有自己的控制面板，因此允许控制面板的同源请求，保留正常按钮操作。

### 2. 工具历史不能只看编号

可以把工具调用理解成一张工作单：“读取哪个文件”“执行哪条命令”是内容，调用 ID 是编号。

原来只凭编号从缓存拿工作单。现在还会检查工具全名和具体参数；编号相同、内容不同时，不会拿另一条调用的参数覆盖当前历史。参数只是换了空白或键顺序时，仍能匹配原来的调用。

另外，多个工具组成一批时，先验证完整批次，再保存缓存和交给客户端。后面的工具无效时，前面的工具不会先污染历史缓存。

这修复了同 ID、不同内容的碰撞；当前数据库仍是个人本机使用的缓存，不是多账号或多租户的隔离数据库。

### 3. 看图先检查，再上传

新增内嵌图片的 MIME、base64、数量和大小检查：单张最多 20 MiB，每请求最多 20 张，解码后合计最多 32 MiB。工具返回的截图也计入。

整个请求的图片检查完成后才开始上传。这样不会出现第二张图片无效、第一张却已经上传的情况。不同图片也不再共用一把上传锁；同一账号同一张图仍只上传一次。

仍沿用 Excel 附件接口，没有增加需要公网访问的临时图片服务器。图片内容本身是否可解析，最终由上游判断。

### 4. 错误提示更明确，日志少留正文

合法 JSON 也可能格式不对，例如传了数组或数字。现在这些请求统一返回 400，并提示必须是 JSON 对象。

损坏 JSON 的错误日志不再打印正文开头或其十六进制表示，只保留长度、路径和编码等信息。

### 5. 文档和旧记录分开放

首页缩短为启动和文档入口；[使用说明](使用说明.md)讲操作；[开发说明](开发说明.md)放接口与代码信息。旧排查记录和已完成计划保存在本地 `tmp/`，保留原内容，避免把旧命令当成当前用法。

文档也按当前页面修正了费用说明：本月显示的是 API 费用估算，不能当作实际账单或 Excel 剩余额度。

## 暂时保留的边界

- **仍使用 Excel 单一上游。** 没有引入 Sub2API 的账号池、计费和分发平台；也没有改成从另一个 Codex 账号自动回退登录，避免悄悄换账号。
- **结构化输出已兼容。** Excel 连接服务采用“提示模型输出 JSON，再在本地校验”的适配，覆盖 Codex 自动标题和元数据摘要。流式消息等待完成项通过校验后再构造事件；无效 JSON、Schema 不符和未完成响应不会作为成功结果显示。这不等于上游原生约束解码。
- **需要完整对话历史。** 不能仅凭 `previous_response_id` 继续请求。
- **本地适配不能保证模型能力。** 上游的权限、限流、服务端提示词和模型行为不受本程序控制，不能把协议修复等同于提升模型智力。
