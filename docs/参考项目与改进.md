## 这次实际改了什么

### 1. 让本地接口真正只给本机使用

原来服务虽然只监听本机，但多数接口没有统一检查请求来自哪里。现在会检查连接地址、Host 和浏览器来源。外部网页、外部 Host、非本机连接会被拒绝，读取请求正文之前就结束。

参考桥接项目直接拒绝所有带 Origin 的浏览器请求。本项目有自己的控制面板，因此允许控制面板的同源请求，保留正常按钮操作。

### 2. 工具历史不能只看编号

可以把工具调用理解成一张工作单：“读取哪个文件”“执行哪条命令”是内容，调用 ID 是编号。

原来只凭编号从缓存拿工作单。现在还会检查工具全名和具体参数；编号相同、内容不同时，不会拿另一条调用的参数覆盖当前历史。参数只是换了空白或键顺序时，仍能匹配原来的调用。

另外，多个工具组成一批时，先验证完整批次，再保存缓存和交给客户端。后面的工具无效时，前面的工具不会先污染历史缓存。

这修复了同 ID、不同内容的碰撞；当前数据库仍是个人本机使用的缓存，不是多账号或多租户的隔离数据库。

### 3. 看图先检查，再上传

新增内嵌图片的 MIME、base64、数量和大小检查：单张最多 20 MiB，每请求最多 20 张，解码后合计最多 32 MiB。工具返回的截图也计入。

整个请求的图片检查完成后才开始上传。这样不会出现第二张图片无效、第一张却已经上传的情况。不同图片也不再共用一把上传锁；同一账号同一张图仍只上传一次。

仍沿用 Excel 附件接口，没有增加需要公网访问的临时图片服务器。图片内容本身是否可解析，最终由上游判断。

### 4. 错误提示更明确，日志少留正文

合法 JSON 也可能格式不对，例如传了数组或数字。现在这些请求统一返回 400，并提示必须是 JSON 对象。

损坏 JSON 的错误日志不再打印正文开头或其十六进制表示，只保留长度、路径和编码等信息。

### 5. 文档和旧记录分开放

首页缩短为启动和文档入口；[使用说明](使用说明.md)讲操作；[开发说明](开发说明.md)放接口与代码信息。旧排查记录和计划移到 [archive](archive/README.md)，保留原内容，避免把旧命令当成当前用法。

文档也按当前页面修正了费用说明：本月显示的是 API 费用估算，不能当作实际账单或 Excel 剩余额度。

## 暂时保留的边界

- **仍使用 Excel 单一上游。** 没有引入 Sub2API 的账号池、计费和分发平台；也没有改成从另一个 Codex 账号自动回退登录，避免悄悄换账号。
- **结构化输出仍不支持。** Sub2API 有“提示模型输出 JSON，再在本地校验”的适配。如果后续需要这项能力，应连同流式内容校验一起做，不能只删掉参数就当作支持。
- **需要完整对话历史。** 不能仅凭 `previous_response_id` 继续请求。
- **本地适配不能保证模型能力。** 上游的权限、限流、服务端提示词和模型行为不受本程序控制，不能把协议修复等同于提升模型智力。

## 如何验证

修改前，273 项现有离线测试通过。新增用例先复现了请求来源、历史碰撞、图片预检查与并发、JSON 格式和日志问题，再修改实现。

修改后，291 项离线回归全部通过；53 个 Python 文件通过语法解析，27 个文档内的本地链接均能找到目标。归档的 19 份旧文档逐字节核对，内容未变。

使用的验证入口是：

```powershell
./.venv/Scripts/python.exe -B tools/test-proxy-contracts.py
```

这些测试使用模拟上游，不消耗真实模型额度。本次没有运行实际账号的模型请求，因此不把离线通过写成真实 Excel / Codex 全流程验收。账号和模型当前是否可用，可在面板手动测试。
